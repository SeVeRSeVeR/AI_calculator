# LLM Server Calculator

Статический русскоязычный калькулятор для подбора сервера локального инференса LLM. Работает целиком в браузере, не отправляет данные на сервер и не использует внешние CDN.

Поддерживаются два режима:

- **Режим A — «От железа к модели»**: задаёте GPU, их количество, контекст, число пользователей, движок и квантизацию; калькулятор проверяет весь каталог моделей, показывает распределение VRAM (веса, KV-кеш, резерв, offload), скорость, рекомендацию платформы и предупреждения для мульти-GPU.
- **Режим B — «От модели к железу»**: задаёте модель и нагрузку; калькулятор подбирает три конфигурации — **MIN**, **OPTIMAL**, **MAX** — либо сообщает **IMPOSSIBLE** с рекомендациями, как сделать задачу выполнимой.

## Возможности

- Расчёт весов, KV-кеша, CUDA-контекста, workspace, NCCL-буфера и offload по формулам `calc v1.0`.
- Per-GPU проверка размещения: модель должна помещаться на каждую карту, а не только в суммарную VRAM.
- MoE: веса считаются по полным параметрам, скорость — по активным.
- `head_dim` и число KV-голов берутся из каталога (значения из `config.json`), а не выводятся из размерности эмбеддинга.
- `util_target` берётся из каталога движков с возможностью переопределения.
- Рекомендация CPU, RAM, NVMe, БП и охлаждения.
- Сортировка результатов, пустые состояния, предупреждения о PCIe TP без NVLink.
- MIN/OPTIMAL/MAX с проверяемым инвариантом `min ≤ optimal ≤ max` по VRAM, RAM, ядрам CPU и мощности БП.
- Случай `optimal == max` показывается отдельно: MAX не дублирует оптимальную конфигурацию.
- Инлайн-валидация, сохранение состояния в `localStorage`, share-link через query-параметры.
- Адаптивная вёрстка, клавиатурная навигация, `aria`-атрибуты, `noscript`-заглушка.
- Версия каталога, версия формул и дата сборки в футере; дисклеймер о погрешности.

## Технологии

- Vite 6, React 19, TypeScript 5, Zustand 5.
- Vitest для unit-тестов.
- AJV + JSON Schema для валидации каталога в CI.
- Собственный CSS, системный стек шрифтов, локальный favicon. Внешних запросов нет.

## Быстрый старт

Требуется Node.js 22+ и npm.

```bash
npm ci
npm run dev
```

`npm run dev` сначала выполняет `prepare:data`: копирует `data/*.json` в `public/data/*.v1.json`. Без этого шага приложение не найдёт каталог.

Сборка и локальный предпросмотр:

```bash
npm run build
npm run preview
```

Проверка собранной статики (поднимает локальный сервер и проверяет маршруты):

```bash
npm run smoke
```

`npm run smoke` запускается после `npm run build`, потому что читает `dist/`.

## Каталог данных

Каталог версионируется. Текущая версия — `2026.11`, дата сбора — `2026-11-16`, версия файлов — `v1`.

| Файл | Содержимое | Количество |
| --- | --- | --- |
| `data/gpus.json` | GPU: VRAM, пропускная способность, TDP, интерконнект, цена | 20 |
| `data/models.json` | Модели, включая MoE | 32 |
| `data/quantizations.json` | Квантизации GPU и GGUF | 11 |
| `data/engines.json` | vLLM, llama.cpp, TGI, SGLang | 4 |
| `data/cpus.json` | CPU: ядра, линии PCIe, TDP, цена | 12 |

Правила обновления:

1. Меняйте файлы в `data/`, а не в `public/data/`.
2. При изменении структуры обновите соответствующую схему в `schemas/`.
3. Проверьте данные: `npm run validate:data`.
4. Если меняется формат или семантика, поднимите версию в `src/data/loader.ts` (`DATA_VERSION`) и в `scripts/copy-data.mjs`.
5. Обновите `DATA_SOURCES.md` и, если меняются допущения, `ASSUMPTIONS.md`.

Поля моделей `n_layers`, `n_kv_heads` и `head_dim` должны соответствовать `config.json` конкретной модели. Для MoE `params_total_b` используется для весов, `params_active_b` — для скорости.

## Формулы и допущения

Формулы вынесены в чистые функции `src/calc/core.ts` и покрыты тестами. Все неоднозначные места помечены в коде комментарием `// ASSUMPTION:` и описаны в [ASSUMPTIONS.md](ASSUMPTIONS.md). Источники данных и методика — в [DATA_SOURCES.md](DATA_SOURCES.md).

Кратко:

- веса = `params_total_b × bytes_per_param × 1.05`;
- KV на токен = `2 × n_layers × n_kv_heads × head_dim × kv_bytes_per_elem / 1e9`;
- резерв = `1.5 ГБ × число GPU + overhead движка`;
- workspace = 5% от доступной VRAM;
- скорость decode ограничена пропускной способностью памяти и активными параметрами;
- offload разрешён только движкам с `offload_supported` (llama.cpp) и не более 50% весов; для MIN-конфигурации — не более 40%.

Расчёт оценочный, погрешность около ±15%. Он не моделирует фрагментацию VRAM, thermal throttling, особенности конкретной версии движка и реальные бенчмарки. Проверяйте выбранную конфигурацию на живом железе.

## Тесты

13 тестов покрывают:

1. Базовый fit 8B/70B на RTX 3060.
2. 2×RTX 4090 и предупреждение PCIe TP.
3. 4×A100, 70B FP16 32K / 50 пользователей и реалистичный FP8-вариант.
4. NO_FIT и непустые рекомендации платформы.
5. MoE: total для весов, active для скорости.
6. Три различимые конфигурации режима B.
7. IMPOSSIBLE с рекомендациями.
8. Случай `max == optimal`.
9. Инварианты `min ≤ optimal ≤ max` на сетке моделей, контекстов и пользователей.
10. Per-GPU footprint.
11. Валидация пустых, отрицательных, дробных и текстовых значений.
12. Сериализация и восстановление share-link.
13. Игнорирование невалидных query-параметров с уведомлением.

Расхождения с иллюстративными ожиданиями из исходного ТЗ для тестов 2, 3 и 8 зафиксированы в `ASSUMPTIONS.md`.

## CI и деплой на GitHub Pages

В репозитории два workflow:

- `.github/workflows/ci.yml` — на pull request и push в любые ветки, кроме `main`: lint, typecheck, tests, AJV-валидация, build, smoke.
- `.github/workflows/deploy.yml` — на push в `main`: повторные проверки, build, публикация `dist/`, затем remote smoke опубликованного URL.

Включение Pages:

1. Запушьте репозиторий на GitHub.
2. Откройте **Settings → Pages**.
3. В **Build and deployment → Source** выберите **GitHub Actions**.
4. Сделайте push в `main` или запустите workflow вручную.

Workflow сам вычисляет `base`:

- для `https://<owner>.github.io` — `/`;
- для project pages `https://<owner>.github.io/<repo>/` — `/<repo>/`.

Для локальной сборки под subpath:

```bash
VITE_BASE=/my-repo/ VITE_REPO_URL=https://github.com/owner/my-repo npm run build
```

`VITE_REPO_URL` включает ссылки футера на GitHub. Без него футер ведёт на локальные копии в `docs/`.

## Ограничения

- Только статика: нет серверного расчёта, аккаунтов и телеметрии.
- Каталог не обновляется автоматически; цены и доступность меняются.
- Оценка tok/s — модель, а не бенчмарк. Реальные значения зависят от движка, батчинга, длины prompt и состояния железа.
- Датацентровые SXM/OAM-карты требуют серверного шасси; калькулятор предупреждает об этом, но не подбирает шасси.
- Unified memory (DGX Spark, Mac Studio) учитывается как общий пул с отдельными предупреждениями; это упрощение.
- Каталог не содержит всех существующих GPU и моделей. Отсутствие модели в списке не означает, что она не запустится.
